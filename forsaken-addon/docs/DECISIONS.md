# Decisions

One line per decision where possible; M1 spike evidence is quoted from a real Bedrock Dedicated Server run
(`tools/bds.mjs` + `tools/spike/`, BDS **1.26.52.3** Linux, 2026-10-01). BDS has no client, so anything visual
(rendering, animations, HUD, forms) is still unverified — see TESTING.md.

## Versions and platform
- **D1** Target Bedrock **1.26.50** stable (BDS download API currently serves hotfix 1.26.52.3), `min_engine_version [1,26,50]`, `@minecraft/server 2.10.0`, `@minecraft/server-ui 2.2.0` (npm `latest`). Entity format 1.26.50, item 1.26.30, block 1.26.20 (the newest folders in Mojang's official JSON schema set). No Beta API, no experiments.
- **D2** TypeScript 5.9.3 (latest 5.x; 7.0 is the new native compiler and was not needed), esbuild 0.28.2 bundles to one `scripts/main.js`, vitest 5.0.3 for unit tests. Only dev dependencies; the runtime depends on nothing but the Minecraft modules.
- **D3** Pure logic never imports `@minecraft/*`; only `main.ts` and `*.mc.ts` do (enforced by `npm run validate`). The game model is tested with fakes instead of module mocks.

## Gameplay systems
- **D4 Virtual HP.** All participants (player and bots) have vanilla damage cancelled in `world.beforeEvents.entityHurt`; FORSAKEN HP lives in the script (`Actor.hp`). Hearts show `hp/maxHp × 20` (rounded up while alive). `/kill`, void and `Entity.kill()` bypass hurt events → `entityDie` treats it as elimination (survivor) or teleports the killer back; falling 3+ blocks below the arena floor teleports to a safe cell. Resistance-255 was rejected because it changes vanilla visuals and can be cleared by milk.
- **D5 Bot movement = script steering.** Bots are custom entities with no AI goals; every tick the adapter applies `impulse = desired/0.695 − velocity` toward the next waypoint of an A* path computed on the arena's own nav grid (the layout is generated by us, so the grid is exact and unit-testable). Native goals (`minecraft:behavior.move_to_block`, marker entities + `nearest_attackable_target`) were rejected: no script API to set a navigation target, a per-bot marker needs one component group per bot, and loop/evade behaviour needs per-tick control. GameTest `SimulatedPlayer` rejected (needs Beta `@minecraft/server-gametest`). Stuck recovery: 1.5 s without progress → re-path; 3 s → teleport to next waypoint; 6 s → teleport to nearest safe cell.
- **D6 Per-character skins** use one `int` entity property `forsaken:character` (enums are limited to 16 values; we need 21 + minions) with `client_sync: true`; the render controller indexes `Array.skins[query.property('forsaken:character')]`. Daemon's cursor blink uses a second texture chosen by `math.mod(math.floor(query.life_time * 2), 2)`.
- **D7 Speed control (players).** The script writes the player's `minecraft:movement` attribute every 2 ticks (only when it changes). Vanilla sprint is ×1.3 of walk, FORSAKEN's is 26/12 ≈ ×2.17, so the attribute is chosen per state: sprinting → `0.1 × sprint/26`, walking → `0.1 × 1.3 × walk/26` (both relative to the vanilla sprint baseline per the brief's §3.10). Fallback `config.playerSpeedMode = "effects"`.
- **D8 Sprint gating.** Stable 2.10.0 has no `InputPermissionCategory` for sprint (enum checked: Camera, Movement, LateralMovement, Sneak, Jump, Mount, Dismount, MoveForward/Backward/Left/Right). Hard lock = vanilla rule "no sprinting at food ≤ 6": hunger is set to 6 while exhausted and to 20 otherwise (`minecraft:player.hunger` attribute; saturation kept at 20 so hunger never drains). Soft lock as backup: while exhausted the movement attribute uses walk speed even if the client sprints. The hunger bar doubles as a stamina gauge (20 → 7 maps stamina 100% → 1%). Peaceful difficulty refills hunger, so the match switches the world to Easy (mob spawning is off) and restores the previous difficulty afterwards.
- **D9 Bot entity** `forsaken:bot` (one entity, properties `forsaken:character` and `forsaken:role`), plus `forsaken:prop` for buildings, traps and pizzas. All spawned entities carry tag `forsaken:runtime` and are purged on world load and at match end.
- **D10 Ability input.** Hotbar slot 1 = main attack (killers) / empty (survivors), slots 2–5 = abilities in wiki order, slot 6 = carried map item (Medkit/Bloxy Cola), slot 9 = Forsaken Menu. Instant abilities fire on `world.afterEvents.itemUse`. Charge/hold abilities (Void Rush, Crystal Pitch, Demonic Pursuit, Spawn Protection, Pray) are **tap to start, tap again to release**, auto-release at max charge; this only needs `itemUse`, which works for any custom item. Killer basic attacks fire on `world.afterEvents.playerSwingStart` (`swingSource === Attack`) when the main weapon is held, so they work when swinging at air. The vanilla `minecraft:cooldown` component (0.05 s) is on every ability item only so `Player.startItemCooldown(category, ticks)` can draw the real cooldown overlay.
- **D11 Generators.** Two block types (`forsaken:generator`, `forsaken:generator_lit`) instead of a block state (one docs page still says custom states need an experiment; two types avoid the question). Repair = **sneak while looking at a generator within 3 blocks** (`isSneaking` + `getBlockFromViewDirection` are polled each tick; holding use on a block is not reliably repeatable). Moving off, taking HP damage, or getting stunned interrupts (wiki: "taking damage or moving at all kicks you out").
- **D12 Generator progress** mirrors the wiki's 5 puzzles: each generator has 5 *layers*; one survivor finishes a layer in 5 s (25 s total, the brief's default), up to 3 repairers solve in parallel (linear, wiki: each repairer has their own puzzle) `[assumed timing]`. Each layer removes 3 s from the clock (wiki 3.6.2), so a full generator removes 15 s.
- **D13 Round clock** (wiki 3.6.2 / 5.1.0): 240 s for 6+ players, +40 s per kill, −3 s per layer; Last Man Standing when one survivor is left: clock set to 75 s and killer/survivor highlighted to each other 3 s every 10 s. Killer dies at 0 HP → survivors win (wiki Statistics / Killers trivia). Blood Hunt blocks a timer end while active (wiki Guest 666).
- **D14 Aura reveal** = `TextPrimitive` label attached to the target (`depthTest=false`, `visibleTo` = viewers) + HUD callout with direction arrow and distance + particle column (`player.spawnParticle`, visible only to the viewer).
- **D15 Status table** comes from the wiki's Status Effects page (Speed/Slowness ±10 %/level and cancel each other level-for-level, Resistance −20 %/level and V = immune, Vulnerable +20 %/level, Weakness −10 % damage *dealt*/level, Strength +20 %, Creatures +25 % taken, Bleeding floor 10 HP, Poison/Corrupted floor 1 HP, Burning can kill and is nullified by Resistance). Vanilla effects are used only for Blindness and Invisibility (same semantics); everything else is script-driven so levels are exact.
- **D16 Stun rules** (wiki 1.1.0 / 5.0.0 / 5.1.0): stun cancels windups/channels; afterwards stun immunity 4 s + 3 s per *additional* living Sentinel; killers are invulnerable during the stun + 1 s; killers have a 0.6 s recovery added to every stun (Guest 1337 page).
- **D17 Arena** is generated in script (no `.mcstructure`): 81×81 floor in the sky (default origin `x=4000, y=220, z=4000`, configurable) so terrain never intersects it; built once (version stamp in a world dynamic property) and only generators/props are reset between matches.
- **D18 Player snapshot.** Before a match the player's inventory, armor, offhand, game mode, location and dimension are saved: items go into two barrels inside a sealed vault under the arena floor (survives reloads); scalars in a player dynamic property. Restored at match end, on abort, and on rejoin if a match was interrupted.
- **D19 Multiplayer.** Only the player who opens the menu takes part; other players are left alone (they can watch from outside). Host leaving aborts the match and the snapshot is restored on rejoin.
- **D20 Wiki over brief.** Where the wiki (read 2026-10-01) differs from the brief's §4, the wiki wins and CHARACTERS.md lists the difference (brief §1.1). The brief's own fallbacks are kept as config switches (`oneXOneHpOverride`, `twoTimeVariant`).
- **D21 Scale.** `STUD_TO_BLOCK = 0.36` for distances; speeds as multiples of survivor sprint (26 studs/s = vanilla sprint 5.612 b/s); seconds, HP, damage and stamina 1:1 (brief §3.10). All conversions live in `src/core/scale.ts`.
- **D22 Forced movement uses the speed scale.** Dashes, lunges, pulls, drags and projectiles convert studs/s with `blocksPerSecond()` (the speed scale of D21), not the distance scale. A Void Rush at 40 studs/s is then 40/26 ≈ 1.5× sprint, the same ratio as in FORSAKEN. Consequence: a dash covers 0.6× the block distance its studs value would suggest, exactly like running does (the whole movement layer is 0.6× the map scale). Static sizes (reach, radii, ranges) keep the distance scale.
- **D23 Presses during a windup.** While an actor has a windup/channel running, other ability presses are refused (`busy`) unless the press releases a charge/toggle ability or the handler sets `usableWhileChanneling`. A new windup replaces a running one only through code, and then calls the old one's `onCancel("replaced")`.
- **D24 Bot CPU budget.** Bots think every 5 ticks (staggered) and steer every tick. Survivor flee planning shares killer distance fields (Dijkstra, 32-block range) between bots: keyed by a 2×2-cell bucket of the remembered killer position, kept 10 ticks, at most one new field per tick. Distance-field values are rounded to float32 before comparison (without this, cells were re-expanded many times: 11 ms → 0.5 ms per field in Node). Paths are re-planned only when stale. Measured in BDS: 8.9 ms average tick over a 443 s bots-only match (was 80 ms before these changes).
